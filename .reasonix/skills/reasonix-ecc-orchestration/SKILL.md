# Reasonix ECC Orchestration（四角色十二层闭环）

> 源：Hermes baseline `ecc-four-role-loop-orchestration` V2.1.0（2026-07-23）
> 吸收方式：**改进吸收**（角色定义+层定义完整保留，适配Reasonix subagent机制）

## 核心定位

本技能只有一个运行主轴：固定十二层。四阶段、四角色、技能调用、时间规则、检查点和返修都必须落入这十二层。

正式长任务要求：真实多智能体、工程执行与独立审计分离、必需技能真实使用、有界返修、可恢复交接。

## 四类真实角色

| 角色 | 职责 | 权限 |
|------|------|------|
| **控制** (control) | 锁定目标、拆包、调度、接收回执、冻结依赖、路由返修 | 唯一维护完整十二层状态 |
| **资料** (materials) | 只读核实来源、准备项目记忆、技能和小型资料包 | 只读 |
| **工程执行** (execution) | 在受控可写空间生成第一版和修复版，只提交执行声明 | 可写（限定空间） |
| **独立审计** (audit) | 从验收标准重新检查并独立接受或拒绝 | 只读 |

"逻辑隔离"不能代替真实子智能体。系统无法启动子智能体时只能标记阻塞。

## 固定十二层

| 层 | 名称 | 责任 |
|----|------|------|
| 1 | Control Plane / 主控调度 | 目标锁定、依赖冻结 |
| 2 | Short Entry / 项目记忆 | 快速加载任务上下文 |
| 3 | Skills / 渐进加载 | 按需加载外部技能 |
| 4 | Planning / 任务拆解 | 拆工作包、分配角色 |
| 5 | Subagents / 上下文隔离 | 启动真实子智能体 |
| 6 | Execution Plane | 生成第一版/修复版 |
| 7 | Hooks / 生命周期钩子 | 前置后置检查点 |
| 8 | Scripts / 确定性检查 | 成功/错误/安全检查 |
| 9 | Verification Plane | 独立接受或拒绝 |
| 10 | Repair Loop | 根因定位+策略改变 |
| 11 | Compact / Handoff | 压缩交接、可恢复 |
| 12 | Final Acceptance | 汇总关口、中文报告 |

## 闭环流程

```text
第6层产生第0轮第一版
→ 第8层运行检查
→ 第9层独立接受/拒绝
→ 拒绝→第10层定位根因+改变策略
→ 返回第6层修复
→ 重新经过第8、9层
→ 通过/部分完成/阻塞/拒绝
```

默认最多 **3 轮返修**。第一轮起必须改变假设/策略/拆包。重复同一失败不计为新轮。

## 最终关口

- 第6层只能声明做了什么
- 第8层脚本通过 ≠ 任务通过
- 第9层必须由不同智能体独立验收
- 第10层必须关闭所有拒绝项
- 第12层只汇总前面已通过的目标/技能/审计/返修

最终状态：通过 / 部分完成 / 阻塞 / 拒绝。面向用户以中文报告。

## 与 Reasonix 原生多智能体的关系

Reasonix 原生 `multi-agent` 命令提供基本子智能体调度。本技能提供：
- **正式角色定义**（不是泛化的"子智能体"）
- **十二层关口链**（不是松散的多智能体协作）
- **独立审计强制分离**（执行者不能验收自己的产物）
- **有界返修**（最多3轮，每轮必须改变策略）

在复杂长任务中优先使用本技能；简单并行任务使用原生 multi-agent。

## 防落灰绑定

- 触发词：复杂长任务、四角色、十二层、ECC、独立审计、有界返修、正式关口。
- 启动流程：先读本文件 → 第3层加载外部技能 → 第4层拆包 → 第5层启动四角色。
