# Reasonix Loop Engineering（长期循环工程）

> 源：Hermes baseline `loop-engineering` V2.0.0（2026-07-23）
> 吸收方式：**直接吸收**（方法论完全适用）

## 核心定位

用一个主循环管理跨时间重复工作：

```text
读取合同与状态
→ 判断是否有新工作
→ 执行或路由
→ 验证
→ 更新状态与追加日志
→ 关闭、等待、返修、阻塞或转人工
```

## 循环类型

| 类型 | 说明 | 停止条件 |
|------|------|----------|
| `goal` | 封闭目标循环 | 目标可验证达成后关闭 |
| `scheduled` | 定时开放循环 | 每轮结束后等待下一周期 |
| `event` | 事件触发循环 | 只处理新事件 |
| `hybrid` | 混合（推荐） | 定时+事件，确定性检查→有工作才唤醒 |

## 每轮硬规则

1. 先读合同和状态，不凭记忆续跑
2. 游标/内容哈希防重复
3. 一轮一个可验证目标或工作包
4. 声明允许/禁止范围、预算、验证器
5. 机械步骤先脚本执行
6. 修改与接受分离（执行者≠审计者）
7. 失败只修复失败部分，不无证据重写
8. 返修后重跑受影响检查
9. 每轮更新 `STATE.json` + 追加 `RUN-LOG.jsonl`
10. 不为制造活动修改原本正确的对象

## 路由到 ECC

满足任一条件输出 `ECC_REQUIRED`：
- 高风险或不可逆
- 3 个及以上相互依赖工作包
- 需要控制/资料/工程执行/独立审计四角色
- 普通 Loop 返修达到上限

## 停止与熔断

立即转为 `BLOCKED` 或 `HUMAN_REQUIRED`：
- 达到最大轮数
- 连续两轮无可测进展
- 同一失败重复两次无新策略
- 需要扩大授权/权限
- 成本或时间达上限

## 产物

每个循环目录：`LOOP-CONTRACT.json`、`STATE.json`、`RUN-LOG.jsonl`。

## 进化循环

定期回顾多轮历史 → `EVOLVE_CANDIDATE`：
- 收紧合同边界
- 删除过时状态
- 机械步骤下沉为脚本
- 稳定SOP固化为技能

## 防落灰绑定

- 触发词：长期循环、定时任务、持续监控、周期检查、重复验证、跨会话轮次。
- 启动检查：先读 `LOOP-CONTRACT.json` → `STATE.json` → 本文件。
