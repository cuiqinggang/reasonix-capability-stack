# Reasonix Evidence-Closed-Loop Repair（证据闭环修复）

> 源：Hermes baseline `evidence-closed-loop-repair`（12道Gate完整方法论）
> 吸收方式：**直接吸收**（方法论完全适用，路径适配）

## 核心原则

**没有被独立、可复核证据证明已经完成的事项，一律视为未完成。** 不验证"看起来是否完成"，只验证：

1. 用户确认的正确内容是否出现在全部必要位置；
2. 错误内容及其别名是否严格为 0；
3. 真源头、生成器、派生文件、镜像母版和最终压缩包是否一致；
4. 最终包是否在全新目录冷启动解压后仍然通过；
5. 每个 PASS 是否绑定路径、计数、哈希、字节比较、截图或语义证据。

## 何时强制启用

- 同一问题已经返工两次；
- 用户反馈"你说改了，但我下载后仍然没改"；
- 修改跨越 5 个以上文件；
- 存在源文件、派生文件、装配文件或稳定母版；
- 最终交付 ZIP、7z、安装包或嵌套压缩包；
- 修改模型名、品牌名、版本号、全局配置或核心规则。

## 十二道 Gate

| Gate | 名称 | 核心动作 |
|------|------|----------|
| 0 | 独立变更合同 | 创建 `CHANGE_CONTRACT.json`：required/forbidden/locked_files/derived/mirrors/deliverables |
| 1 | 全量影响图 | 盘点真源、派生、镜像、脚本、验证器、截图、压缩包等10类对象 |
| 2 | 冻结原版 | 原版只读；记录文件总数、聚合哈希、锁定文件 SHA-256 |
| 3 | 修真源头 | 优先修提示词/模板/配置/生成器；禁止只修最终产物 |
| 4 | 全量重建 | 从修正的源头重新生成全部派生物 |
| 5 | 正向必需项验证 | 每个 required 项：路径+出现次数+期望阈值+实际文本+Pass/Fail |
| 6 | 负向禁止项清零 | 正文/文件名/脚本/截图/ZIP内部，Forbidden 严格为 0 |
| 7 | 派生与镜像一致性 | 装配关系、0号/1号逐字节一致、无旧槽位 |
| 8 | 独立验证器 | Good/Bad 双夹具；验证器不共享生成器替换字典 |
| 9 | 最终包冷启动 | 全新目录解压→递归扫描→对比ZIP/7z逐文件SHA-256 |
| 10 | 视觉和语义证据 | 截图证关键结构；语义检查功能是否成立 |
| 11 | 证据矩阵与分层 | E0(声明)→E1(局部)→E2(全量)→E3(冷启动)→E4(端到端) |
| 12 | 发布纪律 | 新版本号+SHA-256+最终报告+Required/Forbidden量化+冷启动结果 |

## 强制停止条件

- Forbidden > 0
- Required 未达到阈值
- 锁定哈希变化
- 镜像字节不一致
- Good fixture 失败
- Bad fixture 意外通过
- 最终包未冷启动解压

## 防落灰绑定

- 触发词：返工两次、派生不同步、ZIP过期、Forbidden残留、你说改了但还是旧的。
- 启动前检查：先读本文件Gate 0-12，再读 `references/CHANGE-CONTRACT-TEMPLATE.md`。
