# 已知陷阱与修复(生态站 FAILURE-MODES)

> 从 Kilo FAILURE-MODES.md 提炼与 Reasonix 生态站相关的通用陷阱,全部改写为工作区相对语境。
> 每条格式:症状 → 根因 → 如何检测 → 如何修复。
> 本文件同时是 `PASS_WITH_KNOWN_ISSUES` 状态中 known_failures 清单的依据(见 VERIFICATION-LOGIC.md §4)。

## 1. 证据缺失(配置-only 证明)

- 症状:报告写「已生效/已验证」,但没有实际执行证据。
- 根因:只核对了配置、索引、文件存在性,就当成验证通过。
- 检测:核对每条 claim 的证据类型;若全部为 `active_config_confirmed` 而无 `live_call_verified`/测试输出,即命中。
- 修复:对需要真实执行的 claim,实际运行命令/调用并落盘证据;补不了则降级为 PENDING_EVIDENCE。

## 2. 假 PASS(无断言测试)

- 症状:测试全部「通过」,但功能实际是坏的。
- 根因:测试没有真实断言,永远返回成功(always-pass)。
- 检测:审查测试断言数;故意注入错误,观察测试是否变红。
- 修复:给每个测试补有效断言;提交前做必失败注入自检。

## 3. 假 PASS(有响应 ID 但内容为空)

- 症状:调用返回了响应 ID,但内容为空;验证只看 ID 就 PASS。
- 根因:把传输层成功误当内容层成功。
- 检测:检查返回内容是否非空,而不只是看 ID 是否存在。
- 修复:空内容只记 PARTIAL;重试小提示词;仍空则如实报告,不 PASS。

## 4. 假失败(失败-only 验证)

- 症状:所有周期全标 FAIL,但真实执行与产物都在。
- 根因:验证器只搜索异常字符串,不收集成功信号。
- 检测:统计验证器收集的成功信号个数;检查判定逻辑是否只用异常匹配。
- 修复:按双向验证模型同时收集两类信号,加权评分(VERIFICATION-LOGIC.md §2-3)。

## 5. checkpoint 不一致

- 症状:恢复后从错误步骤继续,或重跑已完成步骤。
- 根因:`completed_steps` 与 `next_step` 不一致;或恢复时没读 checkpoint。
- 检测:读 checkpoint JSON,断言 `next_step == max(completed_steps) + 1`。
- 修复:重写 checkpoint 使两者严格一致;恢复时强制从「最后已完成 + 1」继续。

## 6. 索引过期

- 症状:按 registry 索引找文件,路径不存在或内容不是最新。
- 根因:references/skills 增删改后未重跑索引扫描。
- 检测:索引扫描结果与磁盘实际做 diff。
- 修复:每次 references/skills 变更后重跑索引扫描并提交 diff;索引更新是变更的一部分,不做成可选步骤。

## 7. 写入冲突

- 症状:两个会话/任务同时写同一 state 文件,一方覆盖另一方。
- 根因:checkpoint、registry、gate-review 同时写入未加读-合并-写,或未区分归属。
- 检测:对比文件时间戳与内容,出现「后写覆盖前写」的丢失记录。
- 修复:写前先读-合并-再写;每文件带任务标识与时间戳;写入动作在 evidence 留痕。

## 8. 打包仅含目录

- 症状:压缩包打开只有目录,没有实际证据/报告文件。
- 根因:打包时压缩了空目录结构,未校验条目。
- 检测:打包后列出包内条目,确认含真实文件且非空。
- 修复:压缩前先列文件清单;压缩后抽检条目与大小。

## 9. 技能/工具名称混淆

- 症状:因为名字像某个已知能力就选错技能或工具。
- 根因:只看名称近似,没核对能力、适用场景、来源与可用性。
- 检测:核对 SKILL.md 的 description 与内容、registry 索引条目。
- 修复:按「能力描述 → 入口 → 索引 → 用法示例」四步核对后再选。

## 10. 上下文膨胀

- 症状:任务越长上下文越乱,关键状态丢失。
- 根因:把阶段细节全部留在活跃上下文,未移到 references/state。
- 检测:活跃上下文是否包含过多历史阶段细节。
- 修复:重细节写入 references/ 与 state/;活跃上下文只保留:当前请求、当前 claim、最新报告路径、安全边界、下一步动作。

## 11. 报告路径漂移

- 症状:报告引用的证据路径已不存在或被移动。
- 根因:证据文件后续被移动/清理,未同步更新引用。
- 检测:对报告内全部证据路径做存在性检查。
- 修复:报告生成时固定证据路径;移动证据时批量更新引用;引用一律用工作区相对路径。

## 12. 验收标准被放宽

- 症状:为了出 PASS,临时降低验收标准。
- 根因:先看证据再改标准,标准反向适配证据。
- 检测:对比阶段开始前定死的验收标准与最终判定口径是否一致。
- 修复:标准先定后验;不满足就走 Repair Loop 或报 BLOCKED。

## 13. 恢复跳步

- 症状:恢复时为了省事跳过了未验证的步骤。
- 根因:resume 流程没核对 checkpoint 与证据在位。
- 检测:恢复前核对 checkpoint 的 next_step 与证据路径存在性。
- 修复:从 next_step 继续;缺失证据先补证,禁止跳步。

## 14. stderr 误读(命令报「错」实际成功)

- 症状:命令退出码 0、产物正确,但因 stderr 有进度/警告行被误判失败。
- 根因:把 stderr 当作失败信号。
- 检测:查看退出码与产物;区分 stderr 中的进度输出与真实错误。
- 修复:以退出码 + 产物 + 断言为准;stderr 进度行不作为失败信号(VERIFICATION-LOGIC.md T-02)。
