# Coding Rules — Reasonix 成熟生态站

> 适配自 `cursor-kilo-supertool-mature-stack/references/rules/coding-rules.md`；剥离旧环境路径依赖。

## 文件操作

- 编辑前先读取文件内容。
- 保持现有代码风格和缩进。
- 不添加多余注释。
- 优先编辑现有文件，不新建除非必要。
- 所有新增内容只写入当前 Reasonix 工作区与 `.reasonix` 目录（除非任务明确授权其他范围）。

## 代码质量

- 遵循项目现有命名规范和模式。
- 不使用未验证存在的库。
- 保持函数单一职责。
- 不引入安全漏洞或敏感信息泄露。

## 语言规则

- 默认用简体中文回答用户。
- 代码、命令、路径、错误原文、模型名保留英文。
- 回答应分步骤、短句、可操作。

## 验证

- 修改后运行 lint/typecheck（如果项目提供）。
- 不擅自 commit 或 push。
- 不分阶段等待用户确认，连续执行到完成（长任务除外，按 long-task-rules 分段）。

## 禁止

- 不复制旧宿主配置、路由脚本、密钥或旧绝对路径。
- 不写入任何外部 API 密钥字面量。
